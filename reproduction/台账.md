## log 记载约定统一（2026-11-17）—— 只动 1.6pct，4.7pct 一个字节没碰

| 项 | 内容 |
|---|---|
| **动的是谁** | **只有 K29 mimicraw 1.6pct** 的 `test/train/validation` 三份 `modification_log.csv` |
| **没动的是谁** | **K29 mimicraw 4.7pct 的 log 逐字节未动** —— md5 `6e6ba7338c7b99a9bee0a48e31cf9304`（改前 = 改后）✓ |
| **改什么** | 注入器条目的 `clean_value`：**float repr（`'160.0'`）⇒ 原始串（`'160'`）** |
| **md5 指纹** | 1.6pct `test` `763a1fcb2e195d7eaaca80256661c8f5`（改前 `1p6_test__modification_log.csv.pre_rawform.bak`）<br>`train` `d349da58718d98cc489b1082a70adbaa`／`validation` `56d62edc3dd8b81cb383f4323b422392`<br>4.7pct `test` `6e6ba7338c7b99a9bee0a48e31cf9304`（**改前 = 改后** ✓） |
| **规则** | 只转「确为 float repr 的整数」：`float(s)` 是整数 **且** `str(float(s)) == s`。`'160.0'`→`'160'` ✔；`'160'` 不转；**`'04280'` 不转（保留前导零）** |
| **不动的东西** | `dirty_value`（必须与 raw 里实际写入的串一致）；原生错误条目（873 条 `mimic_native_*`）；**所有键列** |
| **脚本** | `reproduction/fix_k29_log_rawform.py`（`--fix` 才写） |
| **改动量** | test 3,236,991 条（`valuenum` 3,205,425 + `amount` 31,566）；train 100；validation 9,030 |
| **核对** | 逐行对比备份：只 `clean_value` 变、只 valuenum/amount 两列、**原生条目 0 改、键列 0 改**、全部「数值相等」、其它列 0 差异 ✓ |

**为什么必须跳过键列 / 保留前导零**：`diagnoses_icd.csv` 的键列含 `icd_code`，
它有 **1,743 条前导零形式**（`'04280'`）。宽松规则（只要是整数就转）会把它们抹成 `'4280'`，
而评分器用 log 的 `clean_value` **按精确字符串**还原被注入破坏的 key ⇒ 还原失败
⇒ 这 **1,743 行**被记成 `row_not_in_gold` 而**排除出评估集**（评估集从 3,671,318 掉到 3,669,575）。
⇒ 严格规则实测**对 4.7pct 的 log 零改动**（该档 log 已是原始串形式 ⇒ 规则幂等）✓

基线 `n18_1.6pct_val_prompt_v1.md` **本来就没有**「原生错误」这一节（N18 母数据集
只有注入层）⇒ 不是替换，是**新增**。生成器 `reproduction/make_n18_mimicraw_prompt.py`
（锚点缺一个就 `SystemExit`，不会静默生成半成品）：

1. **量级三行重算 + 每档追加原生层规模**（train 15 / validation 31 / test 715，
   并标出「其中 N 格是 train/validation 里注入的同形态示例」）
2. **类 1 生理不可能区间**：21 个 itemid ↔ 区间的**完整对照表**
   （按 d_items 的 label 文本匹配 ⇒ 不照抄 i48 的列表）；
   附「train 只见过 4 个，其余 13 个 test 上会出现 ⇒ 按整张表实现」
3. **类 2 哨兵占位码**：10 个 MIMIC 占位码 + **「清单不是封闭的」**
   （实测注入层脏值 top = `-1`(79.4 万) / `9999`(79.4 万) / `-888`(79.2 万) / `-999`(79.2 万)
   ⇒ **`-1` 和 `-888` 不在 MIMIC 清单里**，只认清单 = 这类错误一格都修不掉
   —— 这是 icu5000 4.7pct 漏修 281 万格的同一个坑）
4. **itemid 别名注入节**：`chart_itemid_alias_split` 实测 **484,021 条，规则符合率 100.00%**
   （还原规则 `原 itemid = "2" + alias[3] + alias[-4:]`，与 icu5000/i48 同型但**自己验过**）
5. **train 的 15 组可对照例子**：itemid / 脏值 / 合理区间 / 池子范围 / 中位数 / reference 的修复值
   ⚠️ **池子必须从「源 reference」复算、且排除坏格自己**
   （构建器口径：`med = median(us \ {坏格})`）⇒ 生成时用同一算法复算，
   **15/15 组中位数与 log 逐位一致**（这条本身就是对生成器的自检）。
