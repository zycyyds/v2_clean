# 实体对齐错误纠正

## 适用条件

- 多个编号、代码、名称或写法可能表示同一指标、药物、诊断或其他业务实体。
- 每个取值单独看都合法，但拆分后造成频次稀释、语义重复或不一致聚合。
- 如果矛盾只涉及表内范围或必须跨表验证业务关系，同时参考对应错误 View Skill。

## 证据要求

- 比较候选实体的字段结构、上下文列、取值分布、单位、事件时间和共现对象。
- 在成对标准示例中寻找可重复的一对一归一化关系。
- 优先使用数据内可验证证据；有授权词典时可作为补充，但不能替代当前数据验证。
- 名称相似或编号稀有只能产生候选，不能单独证明实体等价。

## 推荐工具

- 用 `InspectDataFile` 比较候选实体的频次、单位、上下文字段和取值分布。
- 用 `CompareArtifact` 检查成对示例中的归一化方向是否稳定且唯一。
- 用 `ExecutePython` 运行 workspace 中的只读共现、映射一致性和冲突统计脚本；映射文件只能由当前证据生成。

## 执行步骤

1. 按实体字段统计频次、上下文和分布，找出疑似别名或拆分表达。
2. 使用 `CompareArtifact` 检查标准示例是否将候选稳定归并到同一规范实体。
3. 验证除实体字段外的关联列和业务语义是否兼容。
4. 建立来源表达至规范表达的确定性映射，并记录证据范围。
5. 应用映射后重新检查频次、重复键、跨表关联和未映射实体。

## 修复与停止条件

- 只有映射方向唯一、在示例中稳定且不会合并不同语义实体时才自动归一化。
- 多个规范实体都可能匹配、单位或分布冲突、上下文不足时保留原表达。
- 归一化造成重复记录时，必须按业务粒度判断是否允许去重，不能机械删除。
- 新数据出现未见表达时重新收集证据，不外推无依据映射。

## 禁止事项

- 不硬编码当前评估数据中的编号、代码、行号或正确答案。
- 不仅凭字符串相似度、共同前缀或低频特征合并实体。
- 不把实体对齐变成无条件的全表替换。
- 不修改无关字段、文件结构或输出格式。
