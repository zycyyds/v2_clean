# 跨表逻辑错误纠正

## 适用条件

- 单张表中的记录形式合法，但与 cohort、标签、实体主表或另一事件表关联后产生矛盾。
- 判断依赖外键、实体归属、跨表时序、标签一致性或临床关系。
- 如果问题在单表内已可证明，优先按单表错误处理；如果根因是任务时间窗，参考任务导向 Skill。

## 证据要求

- 先确认每张表的记录粒度和真实 join key，不根据列名猜测关联关系。
- 统计匹配、缺失、多对一和多对多关系，保留具体冲突计数和示例。
- 使用成对标准示例验证正确关系以及允许存在的例外。
- 临床逻辑规则必须有任务说明、标准示例或授权知识来源支持。

## 推荐工具

- 用 `InspectDataFile` 分别确认各表 schema、记录粒度和候选关联键。
- 用 `CompareArtifact` 验证成对示例中跨表关系和修复结果是否稳定复现。
- 用 `ExecutePython` 在 workspace 运行只读 join、基数和冲突统计；必须输出匹配与未匹配计数，不能静默丢行。

## 执行步骤

1. 建立表级粒度、主键、外键和允许基数关系。
2. 分阶段执行 join，区分未知键、归属冲突、标签冲突和时序冲突。
3. 追溯冲突来源，确认应修改子表、主表还是删除无有效归属的记录。
4. 只实施能由稳定关系唯一确定的修复。
5. 修复后重新计算 key 覆盖、未知 key、重复关系和跨表一致性。

## 修复与停止条件

- 外键目标唯一且由主表明确确定时，可以修复错误关联值。
- 明确无合法父记录且属于人工或损坏记录时，可以删除孤立记录。
- 多个父记录都可能匹配、join key 粒度不清或临床规则存在例外时保持原值。
- 修复会改变正常实体数量、合法一对多关系或大范围记录时立即停止并复查粒度。

## 禁止事项

- 不按错误的替代键去重或合并合法实体。
- 不因为 join 失败就自动选择最接近的主表记录。
- 不把统计相关性当作临床逻辑约束。
- 不读取隐藏答案、历史实验或评分产物来决定修复。
