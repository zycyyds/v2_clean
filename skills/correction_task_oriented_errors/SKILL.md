# 任务导向错误纠正

## 适用条件

- 数据记录本身可能合法，但其时间、来源或信息内容违反当前任务定义。
- 风险包括未来信息、结果代理、标签直接编码、跨 split 统计污染或错误的时间零点。
- 判断必须从任务目标和可观察窗口反推，不能只依赖字段分布。

## 证据要求

- 明确任务预测对象、索引时点、特征窗口、结果窗口和数据 split 边界。
- 将每个特征的产生时间和可获得时间与任务边界比较。
- 检查特征与标签的异常确定性关系，并追溯其业务来源，而不是仅看高相关性。
- 使用成对标准示例确认哪些记录或字段因任务约束被排除。

## 推荐工具

- 用 `InspectDataFile` 核对时间字段、标签字段、来源字段和任务窗口分布。
- 用 `CompareArtifact` 观察成对示例对窗口外记录或泄漏字段的处理方式。
- 用 `ExecutePython` 在 workspace 运行只读时间轴、窗口覆盖和潜在泄漏诊断；不得读取隐藏标签或评分结果。

## 执行步骤

1. 从任务说明和数据契约写出明确的时间轴与信息可见边界。
2. 按表检查事件发生时间、记录可用时间、标签来源和特征生成范围。
3. 识别只有在结果发生后才可获得的信息、直接结果编码和跨 split 污染。
4. 区分业务上真实但任务不可用的数据与格式错误数据。
5. 删除或排除任务不可用记录后，重新检查时间范围、key 覆盖和正常记录保留率。

## 修复与停止条件

- 任务边界明确且记录确定落在可见窗口之外时，可以删除该任务中的记录。
- 特征确定由结果标签或结果后信息构造时，可以从任务结果包中移除。
- 时间语义、索引时点或数据可用时间不明确时停止自动处理并保留记录。
- 不用模型性能下降或相关性变弱作为修复正确性的唯一依据。

## 禁止事项

- 不把所有强预测特征都视为泄漏。
- 不把任务不可用等同于原始临床数据错误。
- 不根据隐藏标签或测试评估结果反向选择清洗规则。
- 不强迫四类先验覆盖所有异常；保留开放探索和未分类结论。
